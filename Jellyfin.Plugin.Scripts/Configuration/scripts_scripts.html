Scripts

A script runs its steps when one of its triggers happens on the server. Item kinds and conditions narrow which events it runs for. Steps can send an HTTP request, message or stop the session, refresh metadata, queue a scheduled task, write to the activity log, or run a command at any path the server can reach.

General
Triggers
The script runs when any of these happen.
Item kinds
Run only for items of these kinds. Leave empty to run for every kind. Applies to playback and library triggers; sign ins and scheduled tasks ignore it.
Conditions
Narrow the events further. With no conditions the script runs for every event that passes its triggers and item kinds.
Steps
Run in order. A failed step stops the rest unless it is set to continue on error. Text fields accept {{NAME}} placeholders, listed under Variables below.
Behavior
After a run, skip this script for the same user and item until this many seconds pass. Use it to keep pause and resume from running a script over and over. 0 turns it off.
A command receives each of these as an environment variable, such as $JF_ITEM_NAME, plus $JF_EVENT_JSON with all of them. In a step's text fields, use {{ITEM_NAME}}, {{ITEM_NAME:json}} inside a JSON string, or {{ITEM_NAME:url}} in a URL. Click one to copy it.
